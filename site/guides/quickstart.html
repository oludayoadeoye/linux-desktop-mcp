Getting started

Quick start

Install the MCP server, start it locally, and connect an agent that supports MCP.

Option A — Linux standalone install

For Linux x86_64 and ARM64, the installer downloads the latest release, verifies its SHA-256 digest, and installs without sudo.

curl -fsSL https://raw.githubusercontent.com/oludayoadeoye/linux-desktop-mcp/master/install.sh | bash
~/.local/bin/desktop-control-mcp status

If you want to run desktop-control-mcp without its full path, add ~/.local/bin to your shell PATH (for example, add export PATH="$HOME/.local/bin:$PATH" to your shell profile, then open a new terminal). This installs the CLI only. It does not provision KDE/Wayland dependencies, the KWin bridge, Playwright MCP, or Firefox.

Option B — uv tool install

uv tool install git+https://github.com/oludayoadeoye/linux-desktop-mcp
linux-desktop-mcp --help
linux-desktop-mcp serve --transport stdio

Option C — Full EndeavourOS / Arch setup

For KDE Plasma on Wayland, use the project installer to configure the desktop bridge and companion services.

git clone https://github.com/oludayoadeoye/linux-desktop-mcp.git
cd linux-desktop-mcp
./scripts/install-arch.sh

Log out and back into KDE after installation so KWin loads its script package. See the complete installation guide ↗.

Run as an MCP server

Use stdio when your agent launches the process directly:

desktop-control-mcp serve --transport stdio

Or start a local Streamable HTTP endpoint:

desktop-control-mcp serve --transport http --host 127.0.0.1 --port 8932
Keep HTTP bound to 127.0.0.1. Do not expose the unauthenticated local endpoint directly to the internet.

Connect your MCP client

For stdio clients, configure the command desktop-control-mcp with arguments ["serve", "--transport", "stdio"]. For client-specific examples and the local HTTP setup, see the full client configuration guide ↗.

Verify the connection

For the standalone Linux install, run ~/.local/bin/desktop-control-mcp status (or desktop-control-mcp status if ~/.local/bin is on your PATH). This command checks the local desktop services and HTTP endpoints; it does not inspect an MCP client's active stdio session.

For stdio, verify the server from your MCP client: confirm that the client reports the server as connected and that its available Desktop Control MCP tools can be listed or invoked. A successful stdio session is not represented by the local service status command.

In a development checkout, run uv run pytest -q to execute the automated test suite.
