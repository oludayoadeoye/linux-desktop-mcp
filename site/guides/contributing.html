Contributing

Small, tested, explainable changes keep a cross-platform desktop project maintainable. Human contributors and AI coding agents follow the same engineering standards.

Before changing code

  1. Read the contribution and agent instructions.
  2. Check the current branch and working tree; preserve existing changes.
  3. Inspect the implementation, its callers, tests, and platform counterparts.
  4. For major architecture or public API changes, discuss the proposal before coding.

Development setup

git clone https://github.com/oludayoadeoye/linux-desktop-mcp.git
cd linux-desktop-mcp
uv sync --locked --group dev
uv run ruff check .
uv run pytest -q

Non-negotiable maintenance rules

  • One focused issue per pull request; no drive-by refactors.
  • Preserve MCP tool names, schemas, CLI behavior, and backend contracts unless a change is agreed and documented.
  • Keep platform-specific code inside the relevant backend.
  • Never fake success for unsupported functionality.
  • Add regression tests for bug fixes and tests for failure paths.
  • Keep unit tests deterministic; mock desktop commands and APIs.
  • Avoid unnecessary dependencies and generated-file churn.
  • Never change a user's desktop settings or machine configuration as part of tests.
  • AI agents must not claim tests or physical platform validation they did not perform.

Checks before opening a pull request

uv run ruff check .
uv run pytest -q
git diff --check

Review the full diff and report exactly which platforms were tested. CI success is not proof of physical desktop testing.

Pull request review

Changes go through a pull request, required CI checks, one independent approval, and conversation resolution. Force pushes and branch deletion are disabled on the protected default branch.
