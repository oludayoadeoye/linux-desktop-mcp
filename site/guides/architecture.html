Under the hood

Architecture

A shared MCP interface delegates desktop operations to native platform backends, keeping agent-facing tools consistent while respecting operating-system differences.

AI agent / MCP client
        ⇅ MCP (stdio or local Streamable HTTP)
Desktop Control MCP server
        ⇅ DesktopBackend contract
   ┌────────────┬────────────┬────────────┐
   │ Linux      │ Windows    │ macOS      │
   │ KDE/Wayland│ Win32      │ Quartz     │
   └────────────┴────────────┴────────────┘

Core components

backends/macos.pymacOS native backend.

cli.pyCommand-line interface and server startup.

Companion services

On Linux KDE/Wayland, window integration uses the KWin bridge and user-session services. Browser automation is provided by a separate Playwright MCP sidecar. These supporting components are not bundled into the standalone Python executable.

Transport

stdio is recommended when the agent launches the process. Streamable HTTP is available for local integrations and binds to 127.0.0.1 by default.

Platform validation

CI and unit tests exercise packaging and mocked platform behavior. The project has a real EndeavourOS Linux desktop demonstration. Physical Windows and macOS interactive validation remains pending; see the current support matrix ↗.
